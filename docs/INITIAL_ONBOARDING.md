# JDSS V3.2.2 최초 실전 진입 (Initial Onboarding)

## 목적

최초 실전 운용에서 USD 50,000 기준 포트폴리오를 한 번에 채우는 부담을 줄이기 위한 **1회성 운영 안전장치**입니다.

이 기능은 V3.2.2의 QQQ/TQQQ/SOXL 목표비중, 추세 판단, SOXX 상대강도, JDSS overlay, HWM75 계산을 바꾸지 않습니다. 전략이 계산한 최종 목표수량에 대해 **위험증가 BUY 한도만 단계적으로 확대**합니다.

## 단계

| 단계 | 최종 전략 목표 대비 누적 한도 | 다음 단계 최소 대기 |
|---|---:|---:|
| 1차 | 50% | 현재 단계 전량 체결 후 미국 거래일 3일 |
| 2차 | 75% | 현재 단계 전량 체결 후 미국 거래일 3일 |
| 3차 | 100% | 전량 체결 시 최초진입 완료 |

예를 들어 전략의 최종 목표가 `QQQ 75% / TQQQ 12.5% / SOXL 12.5%`라면 1차 단계는 각 종목의 최종 목표수량 중 50%까지만 주문 승인을 생성합니다. 2차는 누적 75%, 3차는 누적 100%입니다.

## 중요한 원칙

1. **종목별 임의 분할이 아닙니다.** 전략이 산출한 포트폴리오 전체 목표를 동일한 누적 비율로 제한합니다.
2. **모든 BUY는 기존 2단계 Telegram 승인을 유지합니다.** 최초진입 단계가 열렸다고 자동 매수하지 않습니다.
3. **위험축소 SELL은 우선합니다.** 온보딩 중 시장 상태가 악화되어 목표가 줄면 현재 단계의 축소된 목표까지 자동 위험축소합니다.
4. **단계는 자동으로 건너뛰지 않습니다.** 현재 단계 목표수량 체결 및 최소 3거래일 경과 후 Telegram에서 다음 단계를 열어야 합니다.
5. **3차 완료 후 영구 종료합니다.** 일반 V3.2.2 운용으로 전환되며 최초진입 로직이 다시 자동 시작되지 않습니다.
6. **기존 관리 포지션이 있으면 자동 적용하지 않습니다.** 잘못된 포지션 축소/재진입을 방지하기 위해 `BYPASSED_EXISTING_POSITION` 상태로 보호합니다.

## Telegram 사용

`/onboarding` 또는 `/entry` 명령으로 상태를 확인합니다.

### 시작 전

- 관리 포지션 0주
- allocation 미체결 주문 없음
- SAFE_MODE 아님

조건이 모두 충족되면 `🚀 1차 진입 시작 · 50%` 버튼이 표시됩니다.

### 진행 중

현재 단계의 목표수량이 모두 체결되면 대기 거래일 계산이 시작됩니다. 최소 3 미국 거래일이 지나면 `➡️ 다음 단계 열기 · 누적 75%` 또는 `누적 100%` 버튼이 표시됩니다.

단계를 열면 기존 V3.2.2 allocation BUY 신호가 생성되고, 각 신호는 기존과 동일하게:

1. `1차 · 최신 시세·수량 검토`
2. 최신 가격/허용가/수량 재계산
3. `2차 · 최종 매수 실행`

순서로 처리합니다.

## 설정

`strategy.yaml`의 `market_regime.v322_allocation.initial_onboarding`에서 관리합니다.

```yaml
initial_onboarding:
  enabled: true
  cumulative_fractions: [0.50, 0.75, 1.00]
  minimum_sessions_between_stages: 3
```

## 실거래 잠금과의 관계

이 기능은 실거래 잠금을 해제하지 않습니다. `portfolio.live_enabled: false`, `JDSS_TRADING_MODE=dry_run`, `JDSS_LIVE_CONFIRMATION` 등의 기존 실거래 안전장치는 그대로 유지됩니다.

따라서 최초진입 기능을 dry-run에서 검증할 수 있지만, 실제 주문은 별도의 실거래 승인 절차가 완료되기 전까지 전송되지 않습니다.
