# JDSS 2.2 SGOV 사양

## 1. 목적과 적용 범위

JDSS 2.2는 검증된 2.1 FINAL의 TQQQ·SOXL 신호와 주문 규칙을 유지하면서, 사용하지 않는 전략 배정금을 SGOV로 운용하는 자금관리 계층을 추가한 승인형 단기 스윙 전략이다. 장기 Buy & Hold를 대체하는 전략이 아니라, 제한된 종목별 자금으로 하락 구간의 반등과 대기자금 수익을 함께 추구한다.

- 전략 버전: `JDSS-2.2.0-SGOV`
- 설정·패키지 버전: `2.2.0`
- 대상 종목: `TQQQ`, `SOXL`
- 종목당 전략 자금: `$10,000`
- 기준 봉: 미국 정규장 일봉
- 신호 계산: 정규장 종가가 확정된 뒤 1일 1회
- 매수: 사용자 승인 필수
- 익절·잔여청산: 조건 충족 시 자동 관리 가능
- 자동 손절: 사용하지 않음
- 재매수: 사용하지 않음
- 유휴현금 ETF: `SGOV`
- 계좌 현금 버퍼: `$250`

문서 우선순위는 현재 상태 `CURRENT_WORK.md` → 전략 계약인 이 문서와 실행 설정 `strategy.yaml` → 기능별 운영 문서 순이다. 과거 `Archive`, `Legacy`, v1.x, v2.0 문서는 현재 계약으로 사용하지 않는다.

## 2. 점수 및 최초 진입

모든 매수 단계의 최소 JDSS Score는 55점으로 통일한다.

최초 진입 조건은 다음 조건을 모두 만족해야 한다.

1. 포지션 상태가 `EMPTY`이다.
2. JDSS Score가 55점 이상이다.
3. Reversal Score가 5점 이상이다.
4. 시장 Regime이 `RED`가 아니다.
5. 종목별 추가 가드에 걸리지 않는다.
6. 사용자 2단계 승인을 통과한다.

사용자 승인은 `검토 승인 -> 현재가 재조회·수량 재계산 -> 최종 실행 승인` 순서로 진행한다. 승인 후 가격, 주문수량, 세션 또는 포지션 상태가 바뀌면 기존 승인을 재사용하지 않는다.

총점은 시장 국면 25점, 과매도 40점, 반등 20점, 거래량 10점, ATR 변동성 5점의 합으로 계산하고 `strategy.yaml`의 power calibration을 항목별로 적용한다. 표시 등급은 WATCH 50점, B 72점, A 82점, S 90점 이상이다. 등급은 해석용이며 실제 매수 가능 여부는 55점·반등 5점·시장 국면·현재 포지션·종목별 가드·승인을 모두 평가한 전략 판단을 따른다.

## 3. 포지션 배분과 추가매수

종목별 최대 전략 자금 `$10,000`을 다음과 같이 4단계로 배분한다.

| 단계 | 비중 | 누적 비중 | 최소 Score | 최초 체결가 대비 조건 |
|---|---:|---:|---:|---:|
| 1차 | 40% | 40% | 55 | 최초 진입 신호 |
| 2차 | 30% | 70% | 55 | -2% 이하 |
| 3차 | 20% | 90% | 55 | -5% 이하 |
| 4차 | 10% | 100% | 55 | -7% 이하 |

추가매수 가격 기준은 현재 평단이나 직전 체결가가 아니라 **1차 매수의 실제 최초 체결가**로 고정한다. 하루에는 최대 한 단계만 추가매수할 수 있다.

각 추가매수도 JDSS Score 55점 이상, Reversal Score 5점 이상, `Regime != RED`, 사용자 승인을 모두 요구한다. 가격이 추가매수 기준을 회복한 뒤에는 해당 승인으로 추격매수하지 않는다.

## 4. SOXL 섹터 가드

SOXL은 반도체 섹터 추세 악화 시 일부 진입을 차단한다.

- 벤치마크 후보: `SOXX`, `SMH`
- 기준: 60일 EMA
- 규칙: 사용 가능한 벤치마크 중 하나라도 종가가 EMA60 아래이면 가드 발동
- 차단 단계: **1차, 3차, 4차**
- 2차 추가매수는 차단하지 않음
- 벤치마크 데이터 조회 실패 시: 경고 이벤트를 기록하고 허용(`warn_and_allow`)

이 구조는 최초 진입과 깊은 추가매수에서 섹터 약세 위험을 제한하면서 2차 매수의 회복 기회를 유지하기 위한 최종 채택안이다.

## 5. 익절 규칙

ATR 적응형 익절은 사용하지 않는다. 평단 기준 고정 수익률을 사용한다.

- TP1: 평단 대비 **+4%**, 보유수량의 약 50% 매도
- TP2: 평단 대비 **+6%**, 남은 수량 매도
- 홀수 수량은 TP1에 1주를 더 배정한다.
- 주문가격은 최소 호가단위에 맞춰 올림한다.

매수 또는 추가매수가 체결되어 평단·수량이 변경되면 기존 TP 주문을 취소하고 새 평단과 수량 기준으로 TP 계획을 다시 만든다.

## 6. TP1 이후 잔여청산 규칙

TP1이 목표수량까지 완전히 체결되면 남은 수량은 우선 TP2(+6%)를 계속 목표로 한다. 동시에 **TP1 완전체결 시점 자체를 사이클별 영속 값으로 저장**하고, 이 시점을 기준으로 미국 거래일을 계산한다.

1. TP1 목표수량 완전체결을 확인한다.
2. 해당 사이클의 TP1 완료시점을 `system_state`에 영속 저장한다.
3. 기존 TP2의 체결·취소 상태를 다시 확인한 뒤 필요한 경우 TP2 주문을 재발행한다.
4. 이후 **20개의 완결된 미국 정규장 거래일**이 지나기 전에는 TP2 +6%를 유지한다.
5. TP2가 중간에 취소·거절되어 자동 복구되더라도 20거래일 기준시점은 절대 리셋하지 않는다.
6. TP1 완료 후 20거래일이 지나도록 TP2가 체결되지 않았다면 기존 TP2 주문을 안전하게 취소한다.
7. 취소 과정에서 발생한 마지막 체결수량을 먼저 반영한 뒤, 남은 전량을 **평단 +2%** 지정가 `REMAINDER_EXIT` 주문으로 교체한다.
8. +2% 잔여청산 주문이 취소·거절되면 포지션과 실제 체결수량을 재확인한 뒤 동일 규칙으로 자동 복구한다.
9. 교체 과정에서 기존 TP2가 모두 체결되어 수량이 0이 되면 새 잔여청산 주문을 만들지 않는다.

이 규칙은 손실을 확정하는 자동 손절이 아니다. TP1 이후 장기간 남는 절반의 자금 고착을 줄이기 위한 **수익 상태의 회수 규칙**이다.

백테스트와 실거래는 `remainder_exit_due()`와 `remainder_exit_price()` 공용 코어 함수를 사용한다. 따라서 20거래일 판정과 평단 +2% 호가단위 가격 계산은 두 실행경로에서 동일한 규칙을 따른다.

## 7. 주문 실행 안전장치

### 매수

- 모든 1·2·3·4차 매수는 사용자 승인이 필요하다.
- 매수 검토 시점에 현재가를 다시 조회한다.
- 수수료를 포함해 주문 가능 수량을 다시 계산한다.
- 1차 진입의 추격 상한은 신호 종가 대비 +5%이다.
- 지정가 버퍼는 기본 +0.5%이나, 전략상 허용가격 상한을 넘지 않는다.
- 추가매수는 해당 단계 트리거 가격 위로 회복하면 실행하지 않는다.
- 실제 달러 매수가능금액 부족 시 주문하지 않는다.
- 달러 매수가능금액이 부족하면 JDSS 관리 SGOV를 먼저 매도하고, 체결 확인 전에는 전략 주문을 제출하지 않는다.

### 매도

- TP1, TP2, `REMAINDER_EXIT`는 전략상 자동 매도 주문이다.
- 기존 TP 주문 취소가 확정되지 않으면 충돌 주문을 새로 만들지 않는다.
- 부분체결은 누적 체결수량과 브로커 실제 보유수량을 기준으로 반영한다.
- TP2 취소 직전 추가 체결이 발생하면 해당 체결을 먼저 포지션에 반영한 뒤 남은 수량만 잔여청산한다.
- 중복 주문은 client order id 멱등키로 차단한다.

## 8. 상태 관리 및 재시작 복구

정상적인 주요 흐름은 다음과 같다.

`EMPTY -> WAITING_1ST_FILL -> HOLDING_1ST -> HOLDING_2ND -> HOLDING_3RD -> HOLDING_4TH -> PARTIAL_TP_1 -> EMPTY`

모든 단계가 반드시 발생하는 것은 아니다. TP1 또는 TP2가 먼저 발생하면 그에 맞게 상태가 전환된다.

- TP1 완전체결: `PARTIAL_TP_1`
- TP2 또는 잔여청산 완전체결: `EMPTY`
- 주문 응답 불명·브로커/DB 불일치 등 복구 불가능한 상태: `SAFE_MODE`
- `SAFE_MODE`에서는 신규매수를 허용하지 않는다.

서버 재시작 또는 주기적 재조정 시에는 브로커 실제 보유수량, 로컬 포지션 수량, 활성 TP 계획, 로컬 미체결 주문과 브로커 미체결 주문 ID를 비교한다. `REMAINDER_EXIT`가 정상적으로 열려 있는 상태 역시 정상 전략 주문으로 조정 대상에 포함한다. 불일치가 해소되지 않으면 `SAFE_MODE`로 전환한다.

## 9. 금지 사항

다음 동작은 JDSS 2.2 전략에서 금지한다.

- 자동 손절
- 무승인 자동매수
- 재매수 로직
- `RED` Regime에서의 신규·추가매수
- 1차 체결가가 아닌 이동 평단을 기준으로 추가매수 트리거 변경
- 하나의 거래일에 여러 추가매수 단계를 동시에 실행
- SOXL 섹터 가드를 우회한 1·3·4차 진입
- TP2 운영상 재발행을 이유로 TP1 이후 20거래일 대기시간을 리셋하는 동작
- 기존 개인 SGOV를 JDSS 관리분으로 자동 편입하거나 매도하는 동작
- SGOV 매도 체결을 확인하지 않고 TQQQ/SOXL 매수를 제출하는 동작
- 총 전략 배정금보다 많은 금액을 SGOV에 예치하는 동작

## 10. 백테스트 기준

- 초기 전략자금: 종목별 `$10,000`, 합계 `$20,000`
- 매수 수수료: 0.1%
- 매도 수수료: 0.1%
- 기본 슬리피지: 0.1%
- 신호: T일 완결 일봉
- 백테스트 체결: T+1 기준
- 실거래 체결: 승인 후 허용된 프리마켓/애프터마켓 지정가 주문

백테스트의 가격 체결 시점과 실제 승인 주문 세션은 완전히 동일하지 않으므로, 백테스트 수익률은 실거래 수익률 보장이 아니라 전략 비교·검증 지표로 사용한다.

2.1 FINAL 단독 회귀검증 기준 전체 연구구간 CAGR은 약 8.7%, MDD는 약 -24.7% 수준이었다. 2.2 운영 엔진으로 2011-01-01~2026-08-04를 다시 검증한 결과, `$20,000` 포트폴리오는 최종 `$84,516.03`, 누적수익률 `+322.58%`, CAGR `+9.69%`, MDD `-24.68%`였다. SGOV 기여액은 합계 `$10,810.54`였다. SGOV 상장 전 수익률은 0으로 두고, 상장 후 실제 유휴현금 중 종목별 현금 버퍼 몫을 제외한 금액에만 SGOV 조정종가 일별 수익률을 적용했다.

## 11. 유휴현금 운용

SGOV 유휴현금 운용은 JDSS의 매수·매도 신호를 변경하지 않는 별도 자금관리 계층이다.

1. 목표 SGOV 평가액은 `총 전략 배정금 - TQQQ/SOXL 현재 매수원가 - $250 현금 버퍼`이다.
2. 목표가 현재 JDSS 관리 평가액보다 `$100` 이상 클 때만 추가 예치 지정가 주문을 만든다. SGOV 가격 상승만을 이유로 관리분을 자동 매도하지 않는다.
3. SGOV 매수 지정가는 현재가의 `+0.1%`, 매도 지정가는 `-0.1%` 버퍼를 적용하고 센트 호가로 보정한다.
4. 전략 매수 검토 시 수수료 포함 필요금액과 `$250` 버퍼를 만족하지 못하면 필요한 만큼의 JDSS 관리 SGOV를 먼저 매도한다.
5. SGOV 매도 체결 후 달러 매수가능금액이 확인되기 전에는 TQQQ/SOXL 매수를 제출하지 않는다.
6. SGOV 주문은 `SGOV_SWEEP_BUY`, `SGOV_ENTRY_RELEASE` 목적으로 멱등 저장한다.
7. 부분체결은 브로커 누적 체결수량과 이미 원장에 반영한 수량의 차이만 적용한다.
8. 기존 계좌 SGOV는 비관리 수량으로 간주하며 JDSS 원장에 자동 편입하지 않는다.
9. JDSS 관리 수량이 실제 계좌 SGOV 수량보다 많거나 미체결 주문이 불일치하면 SGOV `SAFE_MODE`로 신규 전략 매수를 차단한다.
10. `dry_run`에서는 같은 규칙을 메모리 브로커로 검증하고 Toss 주문 API를 호출하지 않는다.
11. 자동 예치는 미국 시장의 프리마켓·정규장·애프터마켓 중에만 시도하고 휴장·폐장 시간에는 새 주문을 만들지 않는다.

## 12. 변경 통제와 실거래 배포 게이트

`strategy.yaml`의 2.2 수치와 이 문서는 같은 전략 계약으로 취급한다. 아래 항목을 바꾸는 경우 버전 상승과 백테스트 재검증이 필요하다.

- Score 임계값
- 단계별 비중
- 추가매수 하락폭
- TP1/TP2 수익률
- TP1 이후 대기 거래일 또는 잔여청산 목표
- SOXL 섹터 가드 차단 단계
- 자동 손절·재매수 정책
- SGOV 티커, 현금 버퍼, 최소 주문금액, 지정가 버퍼, 선현금화 정책

실거래 배포 전에는 다음 검증을 모두 통과해야 한다.

1. Ruff 및 전체 단위테스트 CI 통과
2. SGOV 상장 전 0%·상장 후 일별 수익률을 적용한 2.2 전체기간 회귀 백테스트 통과
3. 2단계 매수 승인 Dry Run 검증
4. TP1 부분·완전체결 및 TP2 자동복구 검증
5. TP1 완료시점 영속 저장 및 20거래일 판정 검증
6. TP2 복구가 20거래일 시계를 리셋하지 않는지 검증
7. `REMAINDER_EXIT` 취소·재발행·완전체결 검증
8. 재시작 후 브로커/DB Reconciliation 검증

2.2는 작업 브랜치 검증 단계이며 아직 `main`이나 Oracle에 반영하지 않았다. PR과 CI를 거쳐 `main`에 병합된 뒤에도 최초 Oracle 반영은 `dry_run`으로 제한한다. 위 게이트와 별도 사용자 승인을 모두 통과하기 전에는 실계좌 주문 모드로 전환하지 않는다.
