# JDSS 3.0 MONTHLY_H05 최종 사양

이 문서는 `JDSS-3.0.0-TWIN-H05`의 전략·회계·주문 계약이다. 수치 설정은 루트 `strategy.yaml`, 구현은 `src/jd_holdings`, 현재 배포 상태는 `CURRENT_WORK.md`가 기준이다.

## 1. 범위와 안전 상태

- 총 전략자금: `$20,000`
- 거래 대상: TQQQ, SOXL
- 기초자산: TQQQ→QQQ, SOXL→SOXX
- 유휴자금: SGOV, 최소 현금 버퍼 `$250`
- 운영 단계: `dry_run` 전용
- `portfolio.live_enabled`는 반드시 `false`여야 한다.
- V3 설정으로 프로세스를 `live`에서 시작하거나 코어 매수를 live 주문으로 실행하면 코드가 거부한다.
- 이번 승격은 전략·모의운영 승격이며 실계좌 승격이 아니다.

## 2. 월간 쌍발 코어

각 기초자산은 독립적으로 다음 규칙을 적용한다.

1. NYSE의 완료된 마지막 월말 거래일을 확정한다.
2. 해당 월말까지의 월별 마지막 조정종가로 10개월 단순이동평균을 계산한다.
3. 월말 종가가 10개월 평균보다 엄격히 높으면 대응 레버리지 ETF 코어를 ON, 같거나 낮으면 OFF로 둔다.
4. ON 목표는 신호별 총 계좌 평가액의 15%, OFF 목표는 0%다.
5. 목표수량은 매수 수수료를 포함해 정수주 내림한다.
6. 목표와 현재 코어 차이가 총 평가액의 0.5% 미만이면 거래하지 않는다.
7. 신호는 완료 월말 뒤 첫 허용 세션에서 처리한다. 서버가 재시작되면 직전 미처리 월말 신호를 한 번 복구한다.

코어 매수는 검토 토큰과 60초 최종 실행 토큰을 사용하는 Telegram 2단계 승인이 필요하다. 추세 OFF 또는 목표 초과로 발생한 코어 매도는 위험축소이므로 자동 제출한다. 코어 주문 목적은 `CORE_REBALANCE_BUY`와 `CORE_REBALANCE_SELL`이며 누적 체결량을 멱등 적용한다.

## 3. JDSS H05 부스터

기존 JDSS 2.2 과매도·반등 규칙은 종목별 `$1,000`, 즉 초기 총자금의 최대 5% 부스터로 유지한다.

- 진입 최소점수 55, 반등점수 최소 5, RED 국면 신규·추가매수 차단
- 4단계 비중: 40% / 30% / 20% / 10%
- 추가매수: 최초 체결가 대비 -2% / -5% / -7%
- SOXL 섹터 가드: SOXX 또는 SMH가 EMA60 아래면 1·3·4차 차단
- 익절: 평단 +4%에서 약 50%, +6%에서 잔량
- TP1 완전체결 뒤 20개 완료 거래일 동안 TP2 미체결 시 평단 +2% 잔여청산
- 자동손절과 재매수 비활성화
- 모든 부스터 매수는 기존 2단계 Telegram 승인 필수

부스터 `$1,000`은 상향 추종 목표가 아니라 종목별 절대 상한이다. 여기서 H05는 초기 총자금 대비 5%를 뜻하며, 이후 평가액 변동에 맞춰 한도를 늘리지 않는다.

## 4. 통합 계좌와 원장

- `positions`는 JDSS 부스터 수량·평단·원가·TP 상태만 기록한다.
- `core_positions`는 코어 수량·평단·원가·추세·목표비중·신호일을 기록한다.
- 브로커 TQQQ·SOXL 수량의 기대값은 `부스터 수량 + 코어 수량`이다.
- TP 주문수량 검증은 부스터 수량만 대상으로 한다.
- 코어와 부스터 체결은 각 원장에만 반영하며 같은 슬리브의 누적 체결을 두 번 적용하지 않는다.
- 재시작한 dry-run 브로커는 두 원장의 수량과 SGOV 관리수량을 합쳐 복구한다.
- 수량·미체결 주문·SGOV 관리원장이 브로커와 다르면 신규매수를 중단하고 SAFE_MODE 이벤트를 기록한다.

## 5. SGOV 자금관리

SGOV 목표금액은 `총 전략자금 - 코어 원가 - 부스터 원가 - $250`이다.

- `$100` 이상 차이만 조정한다.
- 매수는 최우선 매도호가 +`$0.01`, 매도는 최우선 매수호가 -`$0.01`의 시장가성 지정가를 사용한다.
- 60초 미체결 주문은 취소한 뒤 다음 점검에서 재가격한다.
- 전략 매수 전에 필요한 JDSS 관리 SGOV만 먼저 현금화하고 체결·달러 주문가능금액을 확인한다.
- 기존 개인 SGOV는 관리원장에 자동 편입하거나 자동 매도하지 않는다.
- 활성 승인·매수·현금화 의도가 있으면 재예치를 보류한다.

## 6. 신호와 주문 안전장치

- 일봉과 월봉은 모두 완료봉만 사용한다.
- 매수 허용 세션은 pre-market과 after-hours이며 regular 세션은 비활성화 상태다.
- 신호가격 대비 추격 상한 5%, 지정가 버퍼 0.5%를 적용한다.
- 검토 토큰 TTL 480분, 최종 실행 토큰 TTL 60초다.
- 가격·수량·세션이 최종 승인 뒤 바뀌면 기존 토큰을 폐기하고 재승인을 요구한다.
- 모든 주문은 결정적 `client_order_id`로 예약한 뒤 브로커에 제출한다.
- 부분체결과 재시작 후 주문 조회는 누적 체결량만 추가 반영한다.

## 7. Telegram 계약

- `/portfolio`, `/pf`: 코어 추세·수량·비중, 부스터 수량·원가, 신호 기준일
- `/dashboard`, `/d`: V3 통합 요약과 종목별 코어·부스터 상태
- `/status`, `/s`: 한 종목의 분리 원장과 부스터 TP
- `/score`, `/history`: JDSS 5% 부스터 지표·점수
- `/signal`: 활성 코어·부스터 매수 승인
- `/bt`: V3 전체 포트폴리오 최근 300거래일 통합 백테스트
- `/bt SYMBOL ...`: 단일 종목 JDSS 부스터 백테스트
- `/sgov`: JDSS 관리분·비관리분·목표 유휴자금
- `/ping`: 버전·dry-run·live 잠금

모든 메시지는 Telegram HTML 문법과 4096자 제한을 지키며 긴 백테스트 출력은 안전하게 분할한다.

## 8. 백테스트 계약

V3 통합 백테스트는 코어와 부스터가 현금을 공유하는 단일 계좌로 계산한다.

- 월말 완료봉 신호, 다음 거래일 시가 체결
- 매수·매도 수수료 각 0.1%, 기본 슬리피지 0.1%
- 코어 목표 15%, 부스터는 운영 엔진이 만든 실제 정수주 이벤트를 재생
- 현금 버퍼를 제외한 잔여 현금에 SGOV 일수익률 반영
- 코어·부스터 수량을 분리하고 해당 이벤트의 슬리브만 변경
- 잔여 포지션은 매도 수수료를 반영한 청산가치로 평가
- 누적수익, CAGR, MDD, Sharpe, Sortino, 연도별 수익률, 평균노출과 슬리브별 체결수 제공

CLI `jdss backtest --symbol ALL`과 Telegram `/bt`는 이 통합 엔진을 사용한다. 단일 종목 요청은 부스터 엔진을 사용한다.

## 9. 승격과 배포 게이트

V3 코드를 `main`에 병합하려면 Ruff, 전체 pytest, 설정 검증, dry-run 통합 테스트와 문서 계약 테스트가 통과해야 한다. Oracle 배포는 최신 `main`만 허용하고 서버 `.env`를 강제로 다음 상태로 유지한다.

```dotenv
JDSS_TRADING_MODE=dry_run
JDSS_LIVE_CONFIRMATION=
```

배포 후 `/ping`, `/portfolio`, `/dashboard`, `/signal`, `/bt`, `/sgov`, 서비스 active, DB 마이그레이션, TQQQ·SOXL·SGOV 조회 전용 smoke test를 확인한다. live 승격은 별도 전략 검증·운영자 승인·코드 변경 없이는 불가능하다.
