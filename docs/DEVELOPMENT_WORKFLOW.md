# JD_HOLDINGS 개발 협업 워크플로

## 목적

이 저장소는 집의 Codex 환경과 외부의 ChatGPT 환경을 번갈아 사용해 개발한다. GitHub 원격 저장소를 단일 기준점(Source of Truth)으로 사용하며, 작업 시작과 종료 시 반드시 동기화 절차를 수행한다.

## 작업 환경

- 집: 로컬 저장소 + Codex
- 외부: ChatGPT + GitHub 원격 저장소
- 공통 기준: GitHub의 현재 작업 브랜치
- `main`: 검증된 안정 버전만 반영

## 사용자 단축 지시어

사용자가 아래처럼 짧게 말하면 다음 절차를 자동으로 수행하는 것으로 해석한다.

### `작업 시작`

작업 전에 반드시 다음을 수행한다.

1. 현재 저장소와 브랜치 확인
2. 로컬 환경이면 `git status` 확인
3. 원격 최신 상태 확인
4. 로컬 변경사항이 없으면 `git fetch origin` 후 현재 브랜치를 `git pull --ff-only`로 최신화
5. 로컬 변경사항이 있으면 임의로 덮어쓰거나 stash/reset하지 말고 상태를 사용자에게 보고
6. ChatGPT 환경이면 GitHub의 최신 커밋과 현재 브랜치 파일을 다시 조회
7. 현재 브랜치, 최신 커밋, 미커밋 변경 여부를 간단히 보고한 뒤 작업 시작

로컬 Codex 기준 권장 명령:

```bash
git status
git fetch origin
git pull --ff-only
```

### `작업 종료`

작업 완료 후 반드시 다음을 수행한다.

1. 변경 파일 확인
2. 테스트 및 정적 검사 실행
3. 실패 시 원인을 보고하고, 실패한 상태를 성공으로 표현하지 않음
4. 의도하지 않은 파일이 포함되지 않았는지 확인
5. 변경사항 커밋
6. 현재 작업 브랜치에 push
7. 마지막 커밋 SHA, 테스트 결과, 완료 작업, 남은 작업을 보고

기본 검증 명령:

```bash
pytest
ruff check .
```

프로젝트 설정상 다른 명령이 필요하면 해당 명령을 우선한다.

기본 Git 절차:

```bash
git status
git add <변경파일>
git commit -m "<변경 내용>"
git push origin <현재브랜치>
```

## 핵심 규칙

1. 작업 시작 전 항상 원격 최신 상태를 확인한다.
2. 작업 종료 후 완료된 변경은 commit + push 한다.
3. 같은 브랜치를 집 Codex와 ChatGPT가 동시에 수정하지 않는다.
4. 작업 장소를 바꾸기 전 현재 환경에서 먼저 push 한다.
5. 다음 환경에서는 반드시 최신 원격 상태를 확인한 뒤 시작한다.
6. `main` 직접 개발은 지양하고 기능/검토 브랜치에서 작업한다.
7. 전략 변경은 문서, 설정, 테스트, 코드가 서로 일치하도록 함께 수정한다.
8. 실거래 활성화, 주문 로직, 자금관리 핵심 변경은 별도 검토 후 반영한다.
9. 강제 push, reset, rebase, 대량 삭제 등 파괴적 Git 작업은 사용자의 명시적 승인 없이 수행하지 않는다.
10. 충돌이 발생하면 자동으로 임의 해결하지 말고 충돌 파일과 선택지를 사용자에게 보고한다.

## 브랜치 운영

권장 구조:

```text
main
  └─ feature/review branch
```

개발 또는 전략 검증은 별도 브랜치에서 수행하고, 검증이 끝나면 PR을 통해 `main`에 병합한다.

## 인수인계 체크리스트

Codex와 ChatGPT가 작업을 넘겨받을 때 다음 정보를 기준으로 이어서 작업한다.

- 현재 브랜치
- 마지막 커밋 SHA
- 완료한 작업
- 미완료 작업
- 테스트 결과
- 다음 작업 우선순위
- 전략/설정 변경 여부

## 예시

사용자: `작업 시작`

→ 최신 GitHub 상태 동기화 및 브랜치 상태 확인 후 개발 시작

사용자: `작업 종료`

→ 테스트 → 변경 확인 → commit → push → 결과 보고

이 규칙은 집의 Codex와 외부의 ChatGPT 모두 동일하게 적용한다.
