# JDSS V3.1.1 백테스트 보고서

현재 공식 계약은 [`JDSS_FINAL_SPEC.md`](JDSS_FINAL_SPEC.md)의 **JDSS-3.1.1-TWIN-H40-S3**다. 설정값은 루트 `strategy.yaml`, 정식 재현은 GitHub Actions `JDSS V3 Backtest`와 production `PortfolioBacktestEngine`을 기준으로 한다.

## 1. 이번 버전에서 검증한 것

V3.1.1은 V3.1의 신호·점수·코어·부스터·익절 규칙을 바꾸는 버전이 아니다. 자금계약만 다음처럼 바꿨다.

- 전략원금 $20,000 → **$50,000 고정**
- H40 종목당 cap $8,000 → **$20,000**
- S3 최대 신규투입 $7,200 → **$18,000**
- JDSS 자체수익의 사이징 재투자 → **금지**
- 외부 추가입금의 JDSS 편입 → **금지**
- SGOV → **OFF**
- 유휴원금 → **USD 현금**

백테스트 엔진도 단순히 초기금만 $50,000으로 키운 것이 아니라, 현재 코어·부스터 원가를 별도로 추적해 **누적 실현수익 때문에 신규투입 원가가 $50,000을 넘지 못하도록** 구현했다.

## 2. 공통 백테스트 조건

- 시작: 2011-01-01 이후 사용 가능한 거래일
- 종료: 실행 시점 최신 완료 거래일
- TQQQ/SOXL 코어·부스터 공유계좌
- 코어: QQQ/SOXX 월말 6개월 추세, 첫 ON 10%, 지속 ON 15%
- 부스터: H40-S3, 점수 55, 반등점수 5, 추가매수 -2%/-5%
- TP1 +4% 30%, TP2 +10% 잔량
- SOXL 1·3차 섹터가드
- 매수/매도 수수료: 각 0.10%
- 슬리피지: 0.10%
- 수익 재투자: OFF
- SGOV: OFF
- 잔여 포지션: 매도수수료 반영 청산가치로 평가

## 6. 왜 예전 V3.1의 18.81% CAGR과 다르나

V3.1의 기존 production 연구는 **$20,000 계좌와 SGOV 유휴현금 운용을 포함한 계약**이었다. V3.1.1은 사용자가 선택한 새로운 목적에 맞춰 전략슬리브를 **고정 $50,000, 비복리, SGOV OFF**로 바꿨다.

따라서 두 CAGR은 “같은 자금계약에서 전략이 나빠졌다/좋아졌다”는 직접비교가 아니다. V3.1.1은 수익의 극대화보다 **TQQQ/SOXL에 투입되는 위험예산을 고정하고, 나머지 개인자산을 전략과 분리하는 것**이 목적이다.

V3.2 연구에서는 월급과 이익을 JDSS 사이징에 계속 편입하는 방법도 검토했지만, 사용자는 최종적으로 JDSS를 $50,000 전술 슬리브로 제한하고 나머지 자금은 직접 관리하는 구조를 채택했다.

## 7. 백테스트가 증명하지 못하는 것

백테스트에는 다음 현실변수가 완전히 들어가지 않는다.

- Telegram 승인 지연
- 실제 호가 스프레드
- 지정가 미체결
- API 장애
- 부분체결/UNKNOWN
- 프로세스 재시작 타이밍
- 미래 시장구조 변화

따라서 백테스트는 전략 계산의 검증이고, 운영 안전성은 별도 dry-run·fault-injection·Reconciliation 검증으로 확인한다.

## 8. 채택 판단

V3.1.1은 다음 목적에 맞는 최종 자금계약이다.

> **고위험 TQQQ/SOXL 전략은 최대 $50,000까지만 맡기고, JDSS 자체수익·월급·추가저축은 JDSS 위험예산에서 분리한다.**

SGOV도 제거해 주문·수수료·복구경로를 단순화한다. 전략 신호규칙 자체는 V3.1에서 검증한 TWIN-H40-S3를 유지한다.
