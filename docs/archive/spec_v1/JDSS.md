# JDSS — JH Dynamic Score Swing Strategy (JH 동적 점수형 스윙 전략)

> [!WARNING]
> 이 문서는 **v1.1.2 ~ v1.3** 시절의 레거시(Legacy) 명세서입니다.
> 현재 JDSS 2.2 계약은 [`../../JDSS_FINAL_SPEC.md`](../../JDSS_FINAL_SPEC.md)를 참조하세요.

**전략 명세서(Strategy Specification) v1.1.2 — 공식 기준선(Official Baseline)**

> v1.1.2는 v1.1.1의 전략 로직을 유지하면서, 정규장 종가 신호를 같은 날 애프터마켓 또는 다음 거래일 프리마켓에서 승인·실행할 수 있도록 주문시간 규칙을 보완한 버전이다.

---

## 1. 목적

JDSS는 미국 레버리지 ETF의 **단기 급락 이후 반등 구간**을 공략하는 일봉 기반 점수형 스윙매매 전략이다.

운용 종목:

- TQQQ
- SOXL

종목당 최대 전략자금:

- TQQQ: 10,000 USD
- SOXL: 10,000 USD

총 최대 전략자금:

- 20,000 USD

각 종목은 독립된 매매 사이클(Cycle, 하나의 최초 진입부터 최종 청산까지의 거래 묶음)로 관리한다.

핵심 철학:

> **하락 자체를 사지 않고, 충분히 눌린 상태에서 최소한의 반등 증거가 나타난 구간을 산다.**

## 2. 용어 표기 원칙

문서는 이해하기 쉽도록 **한글을 우선 표기**하고, 개발 시 사용하는 영문 용어를 괄호 안에 병기한다.

| 용어 | 의미 |
|---|---|
| 시장 국면(Regime) | 전체 시장이 상승·중립·하락 중 어느 환경인지 판단한 상태 |
| 필수 통과 조건(Hard Gate) | 만족하지 못하면 점수와 무관하게 매수를 차단하는 조건 |
| 점수(Score) | 매매 후보의 품질을 0~100점으로 평가한 값 |
| 최대 투자허용 비중(Exposure) | 해당 사이클에서 사용할 수 있는 최대 자금 비율 |
| 반등 확인(Reversal) | 급락 후 가격이 실제로 되돌아오기 시작했는지 확인하는 조건 |
| 기준가격(Anchor Price) | 추가매수 하락률을 계산할 때 사용하는 1차 실제 체결가 |
| 추격매수 제한(Entry Chase) | 신호 이후 가격이 급등했을 때 비싸게 따라 사는 것을 방지하는 규칙 |
| 익절(Take Profit, TP) | 목표 수익률 도달 시 자동 매도 |
| 재매수(Rebuy) | TP1 매도 후 다시 과매도 구간이 발생했을 때 일부 수량을 복원하는 매수 |
| 자금 고착(Capital Lock-up) | 포지션이 장기간 청산되지 않아 자금이 묶여 있는 상태 |
| 최대 불리 변동(MAE) | 보유 중 가장 크게 손실이 났던 순간의 손실폭 |

코드의 변수명·상태값·함수명은 구현 일관성을 위해 영어를 유지할 수 있다.

## 3. v1.1.1 로직 검증 결론

현재 단계에서는 신호를 더 줄이는 조건을 추가하지 않는다.

JDSS의 진입 판단은 다음 두 단계로 유지한다.

### 3.1 필수 통과 조건(Hard Gate)

아래 조건은 반드시 만족해야 한다.

- 데이터가 정상적으로 완결되었을 것
- 계좌/주문/DB 상태가 정상일 것
- 허용 자금 한도를 초과하지 않을 것
- 1차 매수 시 시장 국면이 RED가 아닐 것
- 반등 점수(Reversal Score)가 최소 5점일 것
- 사용자 승인이 있을 것

### 3.2 점수(Score)

필수 통과 조건을 만족한 후보만 점수로 품질을 평가한다.

CCI, RSI, 볼린저밴드, 거래량, ATR을 각각 필수조건으로 만들지 않는다.

이유:

- 조건을 모두 AND로 연결하면 매매신호가 지나치게 줄어든다.
- 서로 상관관계가 높은 과매도 지표가 중복 필터로 작동할 수 있다.
- 좋은 후보가 단 하나의 지표 미달로 제거되는 문제를 방지한다.
- 백테스트에서 각 요소의 실제 기여도를 검증한 뒤 필요 없는 요소를 제거하기 쉽다.

## 4. 절대 원칙

1. 전략 계산은 일봉(Daily Candle, 하루 단위 가격봉)만 사용한다.
2. 미국 정규장 종료 후 완결된 일봉으로 하루 한 번 신호를 계산한다.
3. 모든 매수는 사용자 승인 후에만 실행한다.
4. 2~4차 추가매수와 재매수도 사용자 승인 후에만 실행한다.
5. 매수 체결 후 익절 주문(TP)은 자동 관리한다.
6. 자동 가격 손절(Stop Loss)은 사용하지 않는다.
7. 종목당 최대 전략자금 10,000 USD를 초과하지 않는다.
8. RED 시장 국면에서는 신규 1차 매수를 금지한다.
9. RED 시장 국면에서는 추가매수와 재매수도 기본적으로 금지한다.
10. 불확실한 시스템 상태에서는 신규 매수를 금지한다.
11. 전략 수치는 코드에 직접 하드코딩하지 않고 설정 파일로 관리한다.
12. 실거래와 백테스트는 동일한 전략 계산 함수를 사용한다.
13. 전략 변경은 `문서 → 설정 → 테스트 → 코드` 순서로 수행한다.

## 5. 시장 국면(Regime)

SPY와 QQQ의 일봉을 사용한다.

평가 조건:

1. SPY Close > EMA60
2. QQQ Close > EMA60
3. SPY EMA20 > EMA60
4. QQQ EMA20 > EMA60

### 5.1 GREEN(우호적 시장)

4개 조건 모두 만족.

- 신규 매수 정상 허용
- 시장 국면 점수 25점

### 5.2 YELLOW(중립·주의 시장)

GREEN도 RED도 아닌 경우.

- 신규 매수 가능
- 시장 국면 점수 15점
- GREEN보다 강한 과매도·반등 조건이 필요하도록 점수상 불이익 적용

### 5.3 RED(위험 시장)

다음 두 조건을 모두 만족:

```text
SPY Close < SPY EMA60
AND
QQQ Close < QQQ EMA60
```

동작:

- 신규 1차 매수 금지
- 2~4차 추가매수 금지
- 재매수 금지
- 기존 보유 포지션 자동 강제청산은 하지 않음
- 필요하면 `/panic` 또는 수동매도 사용

RED 차단은 신호 희소성을 늘리더라도 유지한다.

이유:

레버리지 ETF에서 시장 전체가 장기추세 아래로 내려간 시점의 물타기는 손실 확대와 자금 고착 위험이 가장 크기 때문이다.

## 6. 사용 지표

### 6.1 CCI(Commodity Channel Index, 상품채널지수)

사용:

- CCI(5)
- CCI(10)

목적:

- 단기 과매도 강도
- 급락 깊이
- 재과매도 판단

### 6.2 RSI(Relative Strength Index, 상대강도지수)

사용:

- RSI(5)
- RSI(14)

목적:

- 단기 및 중기 과매도 강도
- 과매도 후 회복 여부 확인

### 6.3 Bollinger Band(볼린저밴드)

기준:

```text
중심선 = SMA20
상단선 = SMA20 + 2 × 표준편차
하단선 = SMA20 - 2 × 표준편차
```

목적:

- 통계적으로 과도하게 눌린 가격 확인
- 평균회귀 가능성 보조 판단

### 6.4 EMA(Exponential Moving Average, 지수이동평균)

사용:

- EMA5
- EMA20
- EMA60

목적:

- 단기 반등 확인
- 중기 추세 확인
- 시장 국면 판단

### 6.5 ATR(Average True Range, 평균진폭)

사용:

```text
ATR(14)
ATR% = ATR(14) / Close
```

목적:

- 현재 변동성 확인
- 익절폭을 종목 변동성에 맞게 조절

### 6.6 거래량 비율(Volume Ratio)

```text
VolumeRatio = 오늘 거래량 / 최근 20일 평균 거래량
```

목적:

- 급락·반등 구간에서 실제 거래 참여가 증가했는지 확인

거래량은 보조 점수이며 필수조건으로 사용하지 않는다.

### 9.3 RSI5

| 조건 | 점수 |
|---|---:|
| RSI5 > 30 | 0 |
| 25 < RSI5 <= 30 | 3 |

### 9.4 RSI14

| 조건 | 점수 |
|---|---:|
| RSI14 > 40 | 0 |

|---|---:|


## 10. 반등 점수(Reversal Score)

최대 20점.

각 조건 5점:

1. Close > Open
2. Close > Previous Close
3. Close > EMA5
4. ClosePosition >= 0.5

```text
ClosePosition = (Close - Low) / (High - Low)
```

`ClosePosition`은 당일 종가가 일중 고가 쪽에 가까운지를 나타낸다.

### 예외 처리

`High == Low`인 비정상·무변동 봉은:

```text
ClosePosition = 0.0
```

으로 처리한다.

이전 v1.1의 0.5 처리는 실제 반등이 없는데도 반등 5점을 주는 문제가 있어 수정한다.

### 최소 반등 조건

```text
ReversalScore >= 5
```

즉, 네 조건 중 최소 하나만 만족하면 된다.

신호 희소성을 방지하기 위해 10점 이상을 기본 필수조건으로 올리지 않는다.

## 14. 최대 투자허용 비중(Exposure)

점수에 따라 해당 매매 사이클에서 허용되는 최대 자금을 결정한다.

| 현재 유효 점수 | 허용 비중 |
|---|---:|
| 82 ~ 87 | 60% |
| 88 ~ 91 | 80% |
| 92 ~ 100 | 100% |

종목당 최대자금 10,000 USD 기준:

- 60% = 6,000 USD
- 80% = 8,000 USD
- 100% = 10,000 USD

### 14.1 사이클 투자한도(Cycle Exposure Cap)

1차 매수 시 점수로 최초 사이클 투자한도를 결정한다.

예:

```text
1차 Score = 84
→ Cycle Exposure Cap = $6,000
```

이후 추가매수 신호의 점수가 더 높아지면 투자한도를 확대할 수 있다.

예:

```text
기존 Cycle Exposure Cap = $6,000
3차 매수 Score = 90
→ 새 허용한도 = $8,000
```

규칙:

```text
CycleExposureCap =
max(기존 CycleExposureCap, 현재 점수가 허용하는 Exposure)
```

### 14.2 투자한도는 자동으로 줄이지 않는다

점수가 떨어졌다고 이미 보유한 주식을 강제로 줄이지 않는다.

따라서 사이클 투자한도는:

- 상승 가능
- 하락하지 않음
- 종목 최대자금 10,000 USD 초과 금지

이 규칙은 단계별로 서로 다른 MaxExposure를 사용하면서 총 투자금 계산이 뒤틀리는 문제를 방지한다.

## 15. 4단계 분할매수

기본 비중:

| 단계 | 개별 비중 | 누적 비중 |
|---|---:|---:|
| 1차 | 15% | 15% |
| 2차 | 20% | 35% |
| 3차 | 25% | 60% |
| 4차 | 40% | 100% |

### 15.1 단계별 예산 계산

각 단계의 신규 주문금액을 단순히 `현재 한도 × 개별 비중`으로 계산하지 않는다.

사이클 투자한도가 중간에 확대될 수 있기 때문이다.

다음 방식으로 계산한다.

```text
단계 누적목표금액 =
CycleExposureCap × 해당 단계 누적비중

이번 단계 주문예산 =
단계 누적목표금액 - 기존 단계매수 누적금액
```

예:

```text
1차 Score 84
CycleExposureCap = $6,000
1차 누적목표 = $900
→ 1차 약 $900

2차 시 Score 89
CycleExposureCap = $8,000으로 확대
2차 누적목표 = $2,800
기존 단계매수 = $900
→ 2차 신규예산 약 $1,900
```

이 방식으로 최종 단계까지 진행하면 현재 사이클 투자한도와 분할비중이 일치한다.

## 16. 1차 매수

일봉 신호 생성 조건:

```text
State == EMPTY
Regime != RED
Score >= 82
ReversalScore >= 5
SystemHealth == NORMAL
```

실제 주문 실행 조건:

```text
Approval == TRUE

가격 제한 통과
```

## 17. 추가매수 기준가격(Anchor Price)

2~4차 추가매수 하락률은 **1차 실제 체결가**를 기준으로 한다.

```text
AnchorPrice = FirstEntryFillPrice
```

직전 추가매수가를 기준으로 다시 -3%, -5%, -8%를 적용하지 않는다.

이유:

- 단계 간 간격을 명확하게 유지
- 누적 하락률이 의도보다 과도해지는 문제 방지
- 백테스트와 실거래 결과 비교 용이
- 구현 단순화

---

## 18. 추가매수

### 18.1 2차

```text
Close <= AnchorPrice × 0.97
Score >= 84
Regime != RED
ReversalScore >= 5
```

### 18.2 3차

```text
Close <= AnchorPrice × 0.95
Score >= 86
Regime != RED
ReversalScore >= 5
```

### 18.3 4차

```text
Close <= AnchorPrice × 0.92
Score >= 88
Regime != RED
ReversalScore >= 5
```

### 18.4 단계 진행 원칙

- 단계는 순서대로 진행한다.
- 동일 거래일에 두 단계 이상 실행하지 않는다.
- 한 번에 -10%가 급락해도 하루에는 다음 한 단계만 승인한다.
- 이미 완료된 단계를 다시 실행하지 않는다.
- 추가매수 전 사이클 투자한도와 잔여자금을 다시 확인한다.

---

## 19. 추격매수 제한(Entry Chase)

신호 발생 후 다음 거래일 가격이 과도하게 상승하면 매수하지 않는다.

```text
MaxChasePrice = SignalClose × 1.02
```

기본:

```yaml
entry_max_chase_pct: 0.02
```

### 19.1 1차 매수

실시간 현재가가 다음을 만족해야 한다.

```text
CurrentPrice <= MaxChasePrice
```

### 19.2 추가매수

추가매수는 단순히 추격매수 제한만 통과하면 안 된다.

실제 주문 시점에도 원래 추가매수 가격조건이 유지되어야 한다.

예: 2차

```text
CurrentPrice <= AnchorPrice × 0.97
AND
CurrentPrice <= MaxChasePrice
```

따라서 장 마감에는 -3% 이하였지만 다음 날 크게 반등해 -3% 조건을 벗어나면 추가매수하지 않는다.

### 19.3 재매수

재매수도 실제 주문 시점에:

```text
CurrentPrice <= AvgPrice × 0.98
AND
CurrentPrice <= MaxChasePrice
```

를 다시 검증한다.

이 재검증은 잘못된 추격 추가매수를 막기 위한 핵심 안전장치다.

---

## 20. 주문 가능 시간(Trading Session)

JDSS의 **전략 판단 기준가격은 반드시 미국 정규장 종가**이다.

정규장 종료 후 완결된 일봉으로 신호를 생성한 뒤 실제 매수는 다음 시간대에서 사용자 승인을 받아 실행할 수 있다.

### 허용 시간

1. **같은 거래일 애프터마켓(After-Hours, 정규장 종료 후 시간외 거래)**
2. **다음 거래일 프리마켓(Pre-Market, 정규장 개장 전 시간외 거래)**

정규장 중 매수도 기술적으로 가능하지만 JDSS 기본 운용절차에서는 사용하지 않는다.

### 기본 운용 흐름

```text
미국 정규장 종료
↓
정규장 종가 확정
↓
일봉 데이터 완결 확인
↓
JDSS 점수 및 신호 계산
↓
Telegram 알림
↓
대표자 확인
↓
같은 날 애프터마켓 또는 다음 거래일 프리마켓
↓
실시간 가격 재조회
↓
가격조건 재검증
↓
사용자 최종 승인
↓
지정가 매수
```

### 시간외장 주문 원칙

시간외장은 정규장보다 거래량이 적고 호가 간격(Spread, 매수·매도 호가 차이)이 넓어질 수 있으므로:

- 시장가 주문 금지
- 지정가 주문만 허용
- 추격매수 상한 적용
- 추가매수 단계가격 상한 적용
- 재매수 가격 상한 적용
- 주문 직전 실시간 가격 재조회
- 주문이 장시간 미체결되면 자동으로 가격을 올려 따라가지 않음

신호의 판단근거는 시간외 가격으로 다시 계산하지 않는다.

즉:

> **신호 판단은 정규장 종가, 주문가격 판단은 실제 시간외장 현재가**로 분리한다.

---

## 21. 주문가격 상한(Execution Price Ceiling)

매수 지정가 버퍼가 가격 조건을 넘어서는 문제를 방지한다.

기본 지정가 후보:

```text
RawLimitPrice = CurrentPrice × 1.005
```

최종 지정가는:

```text
LimitPrice = min(RawLimitPrice, ExecutionPriceCeiling)
```

`ExecutionPriceCeiling`은 다음과 같다.

### 1차

```text
MaxChasePrice
```

### 추가매수

```text
min(MaxChasePrice, StageTriggerPrice)
```

### 재매수

```text
min(MaxChasePrice, AvgPrice × 0.98)
```

즉, 지정가 버퍼 때문에 전략이 허용한 가격보다 비싸게 체결되는 것을 차단한다.

---

## 22. 익절(Take Profit)

기본:

- TP1 = 평단 대비 +4%
- TP2 = 평단 대비 +8%

수량:

- TP1 = 현재 보유수량의 50%
- TP2 = 나머지
- 홀수 수량이면 TP1에 1주 더 배정

---

## 23. ATR 적응형 익절

```text
TP1Rate = max(4%, 0.8 × ATR%)
TP2Rate = max(8%, 1.6 × ATR%)
```

```text
TP1 = AvgPrice × (1 + TP1Rate)
TP2 = AvgPrice × (1 + TP2Rate)
```

ATR은 주문 시점에 사용할 수 있는 **가장 최근 완결 일봉** 값을 사용한다.

새로운 일봉의 ATR이 바뀌었다는 이유만으로 매일 TP를 변경하지 않는다.

TP를 다시 계산하는 경우:

- 추가매수 실제 체결
- 재매수 실제 체결

---

## 24. TP1 이후 재매수(Rebuy)

재매수는 TP1로 일부 이익을 실현한 뒤 다시 눌림이 발생했을 때만 사용한다.

한 사이클당 최대 1회.

### 23.1 1단계 — TP1 실제 체결

TP1 목표수량이 모두 체결되면:

```text
State = PARTIAL_TP_1
rebuy_watch = true
rebuy_recovery_armed = false
```

### 23.2 2단계 — 회복 확인(Recovery Armed)

TP1 이후 아래 조건 중 하나 이상 만족하면 과매도 회복으로 본다.

- CCI5 > -100
- RSI5 >= 35
- Close > EMA5

```text
rebuy_recovery_armed = true
```

### 23.3 3단계 — 재과매도(Re-Oversold)

회복 확인 후 아래 조건 중 하나 이상 만족:

- CCI5 <= -150
- RSI5 <= 25
- Close <= LowerBand

그리고 다음을 모두 만족:

```text
Score >= 82
ReversalScore >= 5
Close <= AvgPrice × 0.98
Regime != RED
rebuy_recovery_armed == true
rebuy_count == 0
```

사용자 승인 후 실행한다.

### 23.4 재매수 수량

```text
RebuyQty <= 실제 TP1 체결수량
```

또한 재매수 후 현재 포지션 원가가 `CycleExposureCap`을 초과하면 안 된다.

### 23.5 재매수 후 익절계획

재매수가 체결되면:

1. 기존 남은 TP2 주문 취소
2. 실제 보유수량과 평단 재조회
3. 새로운 평단 계산
4. 새로운 TP1/TP2를 현재 전체 보유수량 기준으로 생성

단:

```text
rebuy_count = 1
```

이므로 두 번째 TP1이 체결되어도 추가 재매수는 다시 허용하지 않는다.

## 25. 자동 손절 없음과 위험검토(Risk Review)

JDSS는 자동 가격 손절을 사용하지 않는다.

대신 장기간 자금이 묶이는 상황을 반드시 표시한다.

기본 경고:

| 보유 거래일 | 단계 |
|---|---|
| 10일 | INFO(정보) |
| 20일 | REVIEW(검토 필요) |
| 40일 | HIGH(고위험 검토) |

표시 항목:

- 보유 거래일
- 미실현 손익률
- MAE(최대 불리 변동)
- 현재 시장 국면
- 현재 JDSS 점수
- 평단 회복까지 필요한 상승률
- 현재 자금 고착액

이 경고는 자동 매도 조건이 아니다.

## 27. 비상청산(`/panic`)

동작:

```text
1. 기존 매도 주문 취소 요청
2. 실제 증권사 잔고 재조회
3. 사용자 최종 확인
4. 시장가 전량매도
5. 실제 체결 확인
6. DB/상태 정합성 점검
7. 정상 확인 시 EMPTY
8. 불일치 시 SAFE_MODE
```

체결 확인 없이 상태만 EMPTY로 변경하지 않는다.

---

## 28. 신호 빈도에 대한 기본 방침

현재 전략은 신호를 늘리기 위해 다음을 하지 않는다.

- RED에서 신규진입 허용
- ReversalScore를 0으로 낮춤
- 점수 없이 CCI만 보고 진입
- 하루에 여러 단계 추가매수

대신 다음 값들을 백테스트로 검증한다.

- 진입점수 80 / 82 / 85 / 88
- 반등 최소점수 0 / 5 / 10
- GREEN only vs GREEN + YELLOW
- 거래량 점수 제거 여부
- ATR 진입점수 제거 여부

현재 기본값 `Score >= 82`, `ReversalScore >= 5`, `GREEN + YELLOW`는 **신호 빈도와 안전성 사이의 초기 균형값**으로 유지한다.
