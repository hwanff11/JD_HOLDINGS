# 구현 결정 기록

## D-001 — 프로젝트 격리

- 로컬 경로: `JD_HOLDINGS`
- 패키지: `jd_holdings`
- DB: `data/jdss.db`
- 로그: `logs/jdss.log`
- systemd: `jd_holdings_bot.service`
- 서버 기본 경로: `/home/ubuntu/JD_HOLDINGS`

기존 `cci_nvdl`의 폴더, DB, 로그, 서비스 이름과 겹치지 않는다.

## D-002 — 시장 데이터와 지표

- 장기 연구와 신호는 yfinance 수정주가 일봉을 사용한다.
- 분석은 exchange-calendars의 가장 최근 완결 XNYS 세션까지만 수행한다.
- RSI와 ATR은 Wilder 방식, Bollinger 표준편차는 `ddof=0`을 사용한다.
- 거래량 비율의 20일 기준은 당일 거래량을 제외한다.
- 실주문 현재가는 Toss에서 다시 조회한다. dry-run 현재가는 yfinance 시간외 1분봉을 쓴다.

## D-003 — 주문 안전성

- 모든 매수는 검토와 실행의 일회용 토큰 두 단계를 거친다.
- 원문 토큰은 DB에 저장하지 않고 SHA-256 해시만 저장한다.
- 매수 주문은 전략 상한을 넘지 않는 지정가만 사용한다.
- `clientOrderId`와 로컬 UNIQUE 제약으로 재시도 중복 주문을 차단한다.
- 응답 유실 주문은 UNKNOWN과 대기 상태로 유지하며 새 매수를 막는다.
- DB/브로커 수량 또는 미체결 주문 불일치는 SAFE_MODE로 전환한다.
- TP 부분체결은 누적 수량으로 반영하고 취소된 잔여 주문은 새 revision으로 재생성한다.

## D-004 — 비밀정보와 Git

- `.env`, SSH 키, SQLite, 캐시, 로그, 보고서는 Git에서 제외한다.
- Git remote에는 PAT, OAuth token, 사용자 비밀번호를 넣지 않는다.
- remote는 `https://github.com/<owner>/JD_HOLDINGS.git` 형태만 사용하고 인증은 OS credential helper 또는 GitHub CLI가 담당한다.
- 배포 서버 `.env`는 `0600` 권한을 사용한다.

## D-005 — 승격 기준

`dry_run → live`는 자동 변경하지 않는다. 기준선 백테스트, 전략 개정 및 OOS 검증, Telegram dry-run 관찰, Toss 조회 smoke test, 서버 정합성 검사를 통과하고 운영자가 명시적으로 승인해야 한다.

## D-014 — JDSS-2.2.2-SGOV 현금화 자동 재개와 호가 집행

- SGOV 현금화 의도를 신호별로 DB에 영속화하고, 재시작 후에도 체결과 매수가능금액을 계속 감시한다.
- SGOV 현금화가 완료되면 `/signal` 재실행 없이 TQQQ/SOXL 최종 실행 승인을 자동 재발행하되 최종 주문은 사용자 승인을 계속 요구한다.
- 활성 현금화 의도와 최종 승인 대기 중에는 SGOV 자동 재예치를 차단하고 복수 의도의 예약 현금을 중복 사용하지 않는다.
- SGOV 주문은 최우선 반대 호가보다 1센트 공격적인 시장가성 지정가를 사용한다.
- 60초 미체결 SGOV 주문은 취소 후 최신 호가로 재가격하며, 취소 직전 부분체결을 먼저 원장에 반영한다.
- Telegram 취소는 DB 승인·현금화 의도·연결 SGOV 주문을 실제로 취소한다.
- 시장가 주문은 기본값에서 제외한다.

## D-018 — JDSS-3.1.0-TWIN-H40-S3 연구 후보 채택

- 동일 조건 연구에서 V3.0 대비 V3.1 후보가 CAGR `14.05% → 18.81%`, MDD `-28.29% → -26.04%`, Sharpe `0.835 → 0.940`, Sortino `1.004 → 1.197`로 수익과 위험조정 성과를 함께 개선해 채택한다.
- 월간 추세는 10개월에서 6개월로 단순화하고, 코어는 OFF→ON 첫 달 10%, 추세 지속 시 15%로 운용한다.
- H40의 종목별 자금 상한은 `$8,000`(총자금 40%)이다. S3는 3단계 누적 40%→70%→90%만 사용하므로 정상 한 사이클의 최대 신규투입은 `$7,200`(총자금 36%)이다.
- 추가매수는 -2%와 -5%까지만 사용하고 4차는 제거한다.
- TP1은 +4%에서 약 30%, TP2는 +10%로 변경한다. TP1 이후 기간 기반 잔여청산과 재매수는 비활성화한다.
- 코어와 부스터가 동일 티커를 공유해도 부스터 원장은 해당 부스터 주문의 체결수량·체결가만 사용하고 브로커 합산 평단을 흡수하지 않는다.
- TP 부분체결 후 취소·재주문 시 이전 체결수량을 포함한 누적 TP 체결량을 보존한다.
- live 잠금과 2단계 매수 승인은 유지하며, V3.1 병합과 Oracle 배포는 별개의 게이트로 관리한다.

## D-019 — JDSS-3.1.1 고정 $50k 비복리 자금계약 채택

- V3.1의 6개월 쌍발 코어, H40-S3 진입, -2%/-5% 추가매수, TP1 +4% 30%, TP2 +10%, SOXL 섹터가드는 그대로 유지한다.
- JDSS 위험원금을 **$50,000으로 고정**하고 종목별 H40 cap을 `$20,000`, S3 최대 신규투입액을 `$18,000`으로 스케일한다.
- JDSS 실현수익은 다음 매매 사이징에 재투자하지 않는다. 고정원금보다 큰 실현현금은 Toss 계좌에 남아 있어도 JDSS 주문게이트가 사용하지 못한다.
- JDSS 손실을 개인 USD·월급·추가저축으로 자동 보충하지 않는다. 이후 JDSS 자체 이익으로 손실을 회복해 $50,000 원금까지 돌아오는 것은 허용한다.
- 개인 USD·QQQ·QQQM은 같은 Toss 계좌에 둘 수 있지만 JDSS 원장에서 제외한다. 개인 TQQQ/SOXL은 브로커 수량이 합산되므로 같은 계좌 혼합 보유를 금지한다.
- SGOV 자동운용을 제거하고 `idle_cash.enabled=false`로 고정한다. 미투입 전략원금은 USD 현금으로 유지한다.
- production backtest 결과는 Total Return `+414.80%`, CAGR `11.07%`, MDD `-22.97%`, Sharpe `0.839`, 평균노출 `21.28%`, 최대 원가투입 `$45,951.75`다.
- live 잠금과 2단계 BUY 승인을 유지한다. V3.1.1은 먼저 Oracle forced dry-run으로만 배포한다.
