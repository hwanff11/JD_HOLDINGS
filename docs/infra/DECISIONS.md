# 구현 결정 기록

## D-001 — 프로젝트 격리

- 로컬 경로: `JD_HOLDINGS`
- 패키지: `jd_holdings`
- DB: `data/jdss.db`
- 로그: `logs/jdss.log`
- systemd: `jd_holdings_bot.service`
- 서버 기본 경로: `/home/ubuntu/JD_HOLDINGS`

기존 `cci_nvdl`의 폴더, DB, 로그, 서비스 이름과 겹치지 않는다.

## D-002 — 시장 데이터와 지표

- 장기 연구와 신호는 yfinance 수정주가 일봉을 사용한다.
- 분석은 exchange-calendars의 가장 최근 완결 XNYS 세션까지만 수행한다.
- RSI와 ATR은 Wilder 방식, Bollinger 표준편차는 `ddof=0`을 사용한다.
- 거래량 비율의 20일 기준은 당일 거래량을 제외한다.
- 실주문 현재가는 Toss에서 다시 조회한다. dry-run 현재가는 yfinance 시간외 1분봉을 쓴다.

## D-003 — 주문 안전성

- 모든 매수는 검토와 실행의 일회용 토큰 두 단계를 거친다.
- 원문 토큰은 DB에 저장하지 않고 SHA-256 해시만 저장한다.
- 매수 주문은 전략 상한을 넘지 않는 지정가만 사용한다.
- `clientOrderId`와 로컬 UNIQUE 제약으로 재시도 중복 주문을 차단한다.
- 응답 유실 주문은 UNKNOWN과 대기 상태로 유지하며 새 매수를 막는다.
- DB/브로커 수량 또는 미체결 주문 불일치는 SAFE_MODE로 전환한다.
- TP 부분체결은 누적 수량으로 반영하고 취소된 잔여 주문은 새 revision으로 재생성한다.

## D-004 — 비밀정보와 Git

- `.env`, SSH 키, SQLite, 캐시, 로그, 보고서는 Git에서 제외한다.
- Git remote에는 PAT, OAuth token, 사용자 비밀번호를 넣지 않는다.
- remote는 `https://github.com/<owner>/JD_HOLDINGS.git` 형태만 사용하고 인증은 OS
  credential helper 또는 GitHub CLI가 담당한다.
- 배포 서버 `.env`는 `0600` 권한을 사용한다.

## D-005 — 승격 기준

`dry_run → live`는 자동 변경하지 않는다. 기준선 백테스트, 전략 개정 및 OOS 검증,
Telegram dry-run 관찰, Toss 조회 smoke test, 서버 정합성 검사를 통과하고 운영자가 명시적으로
승인해야 한다.

## D-006 — v1.2.0 점수 재보정

- 총점 100점과 `WATCH 76 / B 82 / A 88 / S 92` 등급 경계는 유지한다.
- 시장·과매도·반등·거래량·ATR 최대점수 `25 / 40 / 20 / 10 / 5`도 유지한다.
- 항목별 원점수에 power curve를 적용하며 지수는 각각
  `1.0 / 0.10 / 0.125 / 0.025 / 1.0`을 사용한다.
- 원점수와 보정점수를 함께 기록한다.
- v1.1.2 설정은 `configs/strategy_v1.1.2.yaml`로 보존한다.
- 잠금 OOS가 양수여도 SOXL 최악 MAE와 고착 위험 때문에 live로 자동 승격하지 않는다.

## D-007 — v1.3.0 진입 병목 완화와 전략 단순화

- 점수 및 `WATCH 76 / B 82 / A 88 / S 92` 등급은 유지한다.
- 최초 진입은 WATCH 76점부터 허용하고, 반등점수의 별도 최소 문턱은 제거한다.
- 종목별 사이클 한도는 고정 10,000달러이며 수익금을 한도에 재투자하지 않는다.
- 1~4차 매수는 `30% / 25% / 25% / 20%`, 추가매수 기준은 최초 체결가 대비
  `-4% / -8% / -15%`다. 추가매수는 B등급 82점 이상을 요구한다.
- 익절은 ATR 조건 없이 `+8% / +16%`로 단순화한다.
- 자동손절, 손절 후 쿨다운, 부분익절 후 재매수는 사용하지 않는다.
- 10/20/40 거래일 위험 검토 알림과 RED 시장 신규매수 차단은 유지한다.

## D-010 — JDSS-2.1.0-FINAL 운영 계약 채택

- 모든 매수 단계 최소 Score를 55로 통일하고 추가매수 기준을 최초 실제 체결가 대비 `-2% / -5% / -7%`로 확정한다.
- TP1/TP2는 평단 대비 `+4% / +6%`로 운용한다.
- TP1 완전체결 후 20개 완결 미국 거래일이 지나도록 TP2가 미체결이면 잔량을 평단 `+2%`의 `REMAINDER_EXIT`로 전환한다.
- SOXL 섹터 가드는 1·3·4차에 적용하고 조회 실패는 경고 후 허용한다.
- 자동손절과 재매수는 사용하지 않으며, 모든 매수는 2단계 사용자 승인을 요구한다.
- 운영 배포는 검증된 `main` 커밋을 강제 `dry_run`으로 반영하고 Toss 조회 전용 smoke test와 Reconciliation 후 별도로 실거래 여부를 판단한다.

## D-012 — JDSS-2.2.0-SGOV 유휴자금 운용 채택

- 2.1 FINAL의 신호·진입·익절 규칙은 그대로 유지하고 SGOV를 별도 자금관리 계층으로 추가한다.
- 총 전략 배정금에서 TQQQ/SOXL 현재 원가와 `$250` 현금 버퍼를 뺀 금액을 SGOV 목표액으로 계산한다.
- 전략 매수에 현금이 부족하면 JDSS 관리 SGOV를 먼저 매도하고 체결·매수가능금액 확인 전에는 본 주문을 차단한다.
- 기존 개인 SGOV는 자동 인수하지 않으며 JDSS가 체결한 수량만 전용 원장과 부분체결 진행값으로 관리한다.
- SGOV 원장 수량이 브로커 수량을 초과하거나 미체결 주문이 불일치하면 SGOV SAFE_MODE로 전략 매수를 막는다.
- Telegram `/cash`와 대시보드에 관리분·비관리분·목표액을 표시하고 `/bt`에는 SGOV 상장 이후 유휴현금 수익률을 반영한다.
- 2.2 역시 최초 운영 반영은 강제 `dry_run`이며 별도 승인 전 SGOV를 포함한 실주문을 활성화하지 않는다.

## D-013 — JDSS-2.2.1-SGOV 명령과 신호 유효성 정리

- SGOV 전용 Telegram 명령을 `/cash`에서 `/sgov`로 변경하고 기존 `/cash` 등록은 제거한다.
- 최신 분석이 진입 게이트를 통과하지 못하면 이전 활성 신호를 `INVALID` 처리한다.
- `/signal` 표시와 승인 전에 버전·점수·반등·RED 국면·만료 게이트를 다시 검증한다.
- 전략 수치는 2.2.0과 동일하며 패키지·설정·표시 버전만 2.2.1로 올린다.
