# JDSS V3.2.2 Release Notes

Release: `v3.2.2`  
Strategy: `JDSS-3.2.2-RS6M-ONEWAY-HWM75`

## 무엇이 바뀌었나

V3.1.1의 저노출 TQQQ/SOXL 직접 스윙 구조를 QQQ 중심 동적 포트폴리오로 재설계했습니다.

- QQQ 기반 0.5 / 1.0 / 1.25 / 1.5x 동적 노출
- QQQ 20일 연환산 변동성 30% 이상이면 0.5x 브레이크
- 새 달 첫 거래일 종가에서 추세/RS6M 상태 reset
- SOXX 126거래일 상대강도 우위 시 leveraged sleeve의 50%를 SOXL로 분산
- 월중 RS 우위 상실 시 SOXL→TQQQ one-way exit
- 기존 JDSS H40-S3는 독립 자금투입 대신 최대 5% QQQ 교체형 virtual overlay 신호엔진으로 전환
- HWM75 controlled compounding: 최고자산 이익의 75%만 위험예산 증가에 반영
- QQQ/TQQQ/SOXL 통합 allocation ledger와 reconciliation
- 모든 위험증가 BUY는 기존 Telegram 2단계 승인 유지
- 위험축소 SELL 자동
- live hard-lock 유지

## 강건성 요약

- SOXL sleeve 25/50/75%에서 성과가 부드럽게 변화해 50%가 단일 최적점 형태는 아니었습니다.
- 반도체 proxy를 SOXX→SMH로 바꿔도 전체 지표가 거의 동일했습니다.
- RS lookback 105/126/147일에서 핵심 CAGR/MDD는 큰 절벽이 없었습니다.
- 월초 판정을 1/6/11 거래일로 이동하면 점진적으로 약해져 timing edge는 있으나 하루짜리 절벽은 아니었습니다.
- 높은 비용 가정에서도 장기 QQQ 초과 CAGR은 유지됐습니다.

## 연구 한계

- 2023+ 데이터는 연구 중 반복 관찰되어 pristine OOS가 아닙니다.
- CSCV-style PBO 약 **64.29%** 경고가 남아 있습니다.
- 과거 백테스트는 미래 초과수익을 보장하지 않습니다.
- 이 경고를 인지한 상태에서 대표 승인으로 production 전략을 V3.2.2로 승격합니다.

## 운영 안전

- Oracle deployment가 `.env`를 `JDSS_TRADING_MODE=dry_run`, 빈 `JDSS_LIVE_CONFIRMATION`으로 강제
- 같은 Toss 계좌 개인 QQQ/TQQQ/SOXL 혼합보유 금지

- Toss smoke test는 read-only이며 주문을 생성하지 않음
